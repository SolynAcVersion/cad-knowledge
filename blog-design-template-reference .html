01

这套版式在解决什么问题

Why a layout system instead of a plain article

技术长文最难的不是写，而是读。读者往往带着一个问题进来，用十秒钟判断"这篇有没有我要的东西"。 纯段落排版把判断成本全压在读者身上；而结构明确的版式，让标题、图表、结论先说话。

所以这份模板把"写作"拆成两件事：内容骨架（章节怎么排）和组件选择（这一节用什么呈现）。 你只需要在既定骨架里挑组件填空，版式一致性由 CSS 保证。

Step 01
选题定位
一句话说清读者读完能做什么
Step 02
拆章节
4–8 个编号章节，每节一个结论
Step 03
挑组件
对比用表格，因果用流程图
Step 04
填正文
卡片写要点，段落写推理
Step 05
校对发布
检查锚点、图注、打印样式
最容易踩的坑：把版式当成内容。 卡片多了会显得零碎，强调色多了会互相抵消。一节的视觉重点最好只有一个—— 要么一张表，要么一个流程图，其余的交给正文。
02

页面骨架：五个层次

Hero → TOC → Section → Figure → Footer

◈深色页头

全页唯一的深色区块，承担标题、导语、署名与关键指标。深色只出现一次，才有分量。

要点：标题里的关键词用渐变字，其余保持白色。

◈粘性目录

等宽小字的横向导航，滚动到哪一节就高亮哪一节，随时知道自己在哪。

要点：锚点、目录、id 三者保持一致。

◈编号章节

描边空心数字 + 主标题 + 等宽英文副标题，形成稳定的阅读节奏。

要点：章节数控制在 4–8 个。

◈内容组件

卡片、表格、流程条、提示块、引用、代码块，六种容器覆盖绝大多数表达需求。

要点：同类信息用同类容器，形成读者预期。

◈图文区

图示与截图统一 1px 描边、16px 圆角、居中等宽图注，视觉重量一致。

要点：图注写"这张图说明了什么"，而不是重复标题。

◈页脚与署名

作者信息、更新时间、原文链接集中在结尾，同时兼作打印页脚。

要点：一处留联系方式就够了。

组件清单：什么信息用什么容器

Pick the container, keep the voice

组件不是装饰，而是语义标签：读者看到表格就知道要横向比较，看到提示块就知道是边界条件。

#标签：六种语义色

主强调对比注意 风险进阶结论
用法：.tag 搭配 .t-blue / .t-cyan / .t-amber / .t-rose / .t-violet / .t-green， 放在卡片标题下方、正文之前，用颜色标注内容的性质。

版式的作用不是让文章变好看，而是让读者在三十秒内知道该读哪一段。

04

从大纲到成文的五步

Outline → Components → Draft → Verify
1
先写结论文，再写开篇。每节先落一句"这节要证明什么"，再补论证与例子。没有结论的段落，多数是可以在编辑时删掉的。
2
把"对比"翻译成表格。凡是出现三处以上"而 X 则……"的段落，改写成表格通常更短也更清楚。
3
把"顺序"翻译成流程条。五步以内的线性过程横向铺开，读者一次就能看全。
4
风险单独成块。失败条件、已知限制、"不要这么做"放在 .callout.rose 或 .warn 里，避免淹在正文中。
5
最后跑一遍锚点。目录每一项都能跳到目标章节，页面在窄屏和打印视图下都不塌。

落地细节：复制即用

Single file · No build · Print friendly

下面是最常用的一张卡片。把 style 里的两个颜色变量换成蓝 / 青 / 紫 / 琥珀 / 绿， 就得到不同语义的卡片，不需要新增 CSS。 

<!-- 一张卡片：图标 + 标题 + 标签 + 正文 + 结论 -->
<div class="grid g2">
  <div class="card">
    <h3>
      <span class="ico" style="background:var(--blue-soft);color:var(--blue)">A</span>
      标题
    </h3>
    <div><span class="tag t-blue">标签</span></div>
    <p>正文，一段话讲清一件事。</p>
    <div class="mot"><b>结论：</b>一句话收口。</div>
  </div>
</div>
零构建：整份文件只有一个 HTML，样式与脚本内联，放进静态站点、邮件附件或本地打开都能正常渲染。 外部只有两处 CDN：三款字体（Space Grotesk / JetBrains Mono / Noto Sans SC）与公式引擎 KaTeX—— 字体离线自动回退到系统字体，公式则降级成 LaTeX 源码，见 07 章节。
  • 换配色：只改 :root 里的色板变量。
  • 换字体：改 --display / --mono / --sans 三个变量，并同步替换字体链接。
  • 加章节：复制一个 <section>，同步改 id 和目录链接。
  • 不需要的模块：直接删，剩下的不会走形。
06

常见坑与取舍

What breaks the layout
窄屏表格会横向溢出。 表格最小宽度约 760px，四列以上在手机上需要横向滚动。列很多时，优先拆成两张表，或把次要列移进卡片。
强调色不要混用。 同一节里出现三种以上语义色，读者就无法判断哪个才是重点。整篇建议只有一种"主强调色"，其余颜色只用于风险与结论。
动画要能降级。 入场动画依赖 IntersectionObserver；脚本不可用时全部内容直接显示（本模板已做兜底），打印视图同样关闭动画。
07

公式与 LaTeX

KaTeX · inline math · display math · \tag{n} · offline fallback
公式未渲染：渲染器没加载成功。 页面已自动降级——公式位置显示等宽 LaTeX 源码，版式不塌。联网刷新即可恢复； 需要彻底离线，见本节最后一段的三步替换。

模板内置 KaTeX 做公式渲染，并让它复用正文的描边与圆角语言：行内公式跟随正文基线， 行间公式自动变成一张公式卡片，窄屏下横向滚动而不是撑破版心。写法与 Markdown 数学块一致，共四种定界符。

行内公式直接写在句子里：注意力机制的复杂度是 $O(n^{2}d)$，状态空间模型把它压到 $O(nd)$； 超参数也照写不误，例如学习率 $\eta = 3\times 10^{-4}$、批大小 $B = 64$、 维度 $d_{\text{model}} = 512$。公式与中文混排时，基线由 KaTeX 自己对齐，不需要手工调行高。

$$ \mathcal{L}_{\text{FM}}(\theta) = \mathbb{E}_{t,x_0,x_1}\Big\|\, v_\theta(x_t,t) - (x_1 - x_0) \,\Big\|_2^{2}, \qquad x_t = (1-t)\,x_0 + t\,x_1 \tag{1} $$
$$ \begin{aligned} \operatorname{Attn}(Q,K,V) &= \operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V \\[2pt] \hat{y} &= W_o \operatorname{Attn}(Q,K,V) + b_o \end{aligned} \tag{2} $$
$$ \text{valid}(M) = \begin{cases} 1, & \delta(M) \le \varepsilon \\[2pt] 0, & \delta(M) > \varepsilon \end{cases} \tag{3} $$
$$ J = \begin{bmatrix} \dfrac{\partial f_1}{\partial x_1} & \cdots & \dfrac{\partial f_1}{\partial x_n} \\[4pt] \vdots & \ddots & \vdots \\[4pt] \dfrac{\partial f_m}{\partial x_1} & \cdots & \dfrac{\partial f_m}{\partial x_n} \end{bmatrix} \tag{4} $$

重复出现的记号可以注册成宏，模板预置了 $\RR$（实数集）、$\dd$（微分算子）与 $\argmax$： 写成 $\dd\mathcal{L}/\dd\theta$ 与 $\theta^{\star} = \argmax_{\theta}\mathcal{L}(\theta)$， 比每次都敲 \mathbb{R}、\operatorname*{arg\,max} 省事得多。 宏定义在页面底部的 macros 里，随项目习惯增删。

写法渲染结果使用场景
$…$行内公式，跟随正文基线变量、符号、短表达式
\(…\)行内公式（LaTeX 原生写法）与 Markdown 混排时更安全
$$…$$ / \[…\]行间公式，居中独立成行完整公式、带编号
\tag{1}公式右侧自动编号正文需要引用某个式子
aligned · cases · bmatrix多行推导 / 分段函数 / 矩阵推导过程与线性代数
两条容易踩的线。 ① 行内 $ 与货币符号冲突：写"售价 $100"要转义成 \$100，否则会被当成公式起点； ② KaTeX 只实现 LaTeX 数学子集——\begin{align} 要写成 aligned， \label / \ref 交叉引用不可用（用 \tag 加手写锚点代替）。 需要完整 LaTeX 生态时，把三个 CDN 地址换成 MathJax 即可，样式不用改。
  • pre / code / script 内的 $ 不会被渲染，贴代码无需转义。
  • 渲染失败时自动加 html.math-offline，公式降级为等宽源码并显示上面的提示条。
  • 公式渲染完成会自动重算目录高亮与阅读进度，长页面不会错位。
三步改成完全离线： ① npm i katex 或直接下载 dist/ 目录； ② 把 head 里的 katex.min.css 与页尾两个 .js 换成本地相对路径； ③ 保留同级的 fonts/ 目录，字体加载同样不走 CDN。
08

结论

Three things worth keeping

1结构先于装饰

编号章节 + 每节一个结论，是长文可读性的下限保障。装饰只负责让结构被看见。

实践：写完大纲再挑组件。

2组件即语义

表格、流程、提示块各有明确含义，混用会让读者失去定位感。

实践：对比用表，顺序用流程，风险用提示块。
